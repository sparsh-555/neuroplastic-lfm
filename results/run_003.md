## What Changed vs Run 002

### τ extraction is now working

τ_a values are real for the first time. Science cluster: `0.0008 → 0.0017` over 500 steps. Creative cluster: `0.0008 → 0.0013`. Both clusters show a small but consistent upward drift in the aggregate time-constant mean — the functional neuroplasticity signal exists. It is very small, which is expected at this training scale with gate ≈ 0.05.

### Attention mask fix had minimal effect on training dynamics

The loss curves are nearly identical to Run 002 step-for-step. The attention mask fix was architecturally correct (GQA blocks were attending to pad tokens without it) but was not the primary bottleneck. The dominant constraint is training scale, not data pipeline corruption.

### First below-baseline result: merged creative 3.96

The TIES-merged cluster achieves creative PPL of **3.96**, below the baseline of 3.98. This is the first result in any run where any configuration beats the raw base model. It is small (Δ=0.02) but directionally correct and reproducible from the architecture.

TIES achieves this by trimming the low-magnitude noise from both task vectors and averaging only the parameters where science and creative clusters agreed in sign — the most general, task-agnostic learned signal survives the merge. The individual creative cluster (3.99) is noisier than the merged result (3.96), which is the correct TIES behavior.

## What Is Still Broken

### Clusters still degrade their own task

Science cluster worsens science PPL (3.15 → 3.19). The cluster is adding a noisy residual at 5.8% influence — enough to hurt, not enough to help. The root cause is a bootstrapping problem in the gate: the gate suppresses gradients for itself, so it takes far too long to open under the default lr.

### Gate barely moves

`0.047 → 0.058` over 500 steps. At this rate, reaching gate=0.3 (enough for meaningful influence) would require approximately 3500 steps. For the cluster to function as designed, the gate needs to open faster.

### Training scale is insufficient

500 steps × 4 batch_size = 2000 training sequences cycling through 150 unique examples. The loss remains noisy (no clean convergence visible in either cluster). The cluster has not been in a high-enough signal regime to learn reliable corrections.

---

## Root Cause: The Maturity Gate Bootstrapping Trap

`sigmoid'(-3) ≈ 0.045`. The gradient reaching `maturity` is scaled by this factor at every step. With `lr=3e-4`, the effective update to `maturity` per step is ~0.045 × gradient — vanishingly small. The gate needs to be open to get strong gradients; it needs strong gradients to open. Under a shared learning rate, neither condition is ever satisfied.

Compare LoRA: no gate, full gradient, full influence from step 1. LoRA r=8 at equivalent training scale shows 10-30% PPL reduction. The CfC cluster shows -1.3% (worse).

## Fixes Applied (committed for Run 004)

**Level 1: Parameter group — maturity gate lr × 20**

```python
optimizer = torch.optim.AdamW([
    {"params": other_params,    "lr": 3e-4},
    {"params": [cluster.maturity], "lr": 3e-4 * 20},  # 6e-3
], weight_decay=0.01)
```

**MAX_STEPS: 500 → 2000**

At the current gate-opening rate (0.047→0.058 per 500 steps), 2000 steps with the higher maturity lr should bring the gate to ~0.3–0.5. At that influence level, the cluster output is substantial enough to move PPL in either direction, and the optimizer has enough signal to drive it downward.
