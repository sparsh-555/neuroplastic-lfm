## Observations

### Gate opened (slightly)

Gate progressed from `0.0474` → `0.0584` over 500 steps for both clusters. The gate is moving in the right direction. At `sigmoid(-3) ≈ 0.047` it started with a real training signal (vs Run 001's `0.0025`), but 500 steps is not enough to open it substantially.

### Clusters degrade performance on both tasks

Both science (3.15 → 3.17) and creative (3.98 → 4.01) got **worse** with clusters applied. The cluster is adding a noisy residual that hurts more than it helps.

The cross-task degradation (science cluster worsening creative PPL) is expected by design — `ppl_cre_A` evaluates the science cluster on creative data, which it was never trained for. The same-task degradation (science cluster worsening science PPL) is the real problem.

### Loss is noisy and non-convergent

Cluster A loss: `0.86 → 1.18 → 1.14 → 1.26 → 1.29 → 0.73 → 1.16 → 1.01 → 1.26 → 0.93`  
Cluster B loss: `2.05 → 1.74 → 1.84 → 1.38 → 1.02 → 1.50 → 1.37 → 1.25 → 1.17 → 1.73`

No consistent convergence trend in either cluster. This is the signature of corrupted gradients.

### τ_a absent from all log lines

Every step log shows no `τ_a=` suffix. The `extract_tau_stats` function was silently returning `{}` at every call because it looked for `cell.time_a` on a `WiredCfCCell`, which has no such attribute (the actual τ parameters live in `cell.layer_0.time_a`, `cell.layer_1.time_a`, `cell.layer_2.time_a`). The core functional neuroplasticity signal was never measured in either run.

### TIES merge recovers exactly to baseline

`θ_merged ≈ θ_init`. When task vectors are mostly noise (clusters didn't converge), TIES-Merging cancels conflicting signs and the result is near-zero updates — equivalent to an untrained cluster. The merge algorithm is correct; the inputs were not.

## Root Causes Identified (counter-analysis)

Three code bugs were confirmed responsible for the failed training:

| Bug | Effect |
|---|---|
| `attention_mask` not stored or passed | All 6 GQA blocks attended to pad tokens; corrupted hidden states fed to cluster; noisy gradients |
| `extract_tau_stats` wrong attribute path | τ signal never measured; `{}` returned silently every call |
| `torch_dtype` deprecated parameter | Warning only, not a crash |

---

## Fixes Applied (committed `8d40f23`, for Run 003)

1. **Attention mask:** `AlpacaDataset` now stores `attention_mask` from the tokenizer. `train.py` and `eval.py` pass it through to `Lfm2Model` via `**kwargs`, correctly masking pad tokens in all GQA blocks.

2. **τ extraction:** `extract_tau_stats` now iterates `cell.layer_0..layer_2`, collecting per-layer `time_a`/`time_b` stats and an aggregate `time_a_mean`. τ will appear in training logs from Run 003 onward.

3. **dtype:** `torch_dtype=torch.bfloat16` → `dtype=torch.bfloat16` in both experiment files.
